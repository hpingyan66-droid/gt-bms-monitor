# 配布パッケージと操作範囲

2026-10-12 / 第1段階。法人用、個人利用者用、フルアクセス用の3種類を同じソースから作成します。開発依頼者の現在の環境はフルアクセスを維持します。ソースの管理・公開にはGit / GitHubを使用する方針です。

## 3種類のパッケージ

| 操作 | 法人用 `corporate` | 個人利用者用 `individual` | フルアクセス `full_access` |
| --- | --- | --- | --- |
| 最新値・警告・履歴・診断の閲覧 | ○ | ○ | ○ |
| 監視の開始・停止 | ○ | ○ | ○ |
| 走行の開始・終了、距離入力 | ○ | ○ | ○ |
| 設定で有効にしたGPSの記録・自分の履歴閲覧 | ○ | ○ | ○ |
| CSV / JSON履歴出力 | ○ | ○ | ○ |
| 取得周期変更・BLE検索・手動バックアップ | × | × | ○ |
| CLIのBLE接続診断・手動バックアップ | × | × | ○ |
| スマホ接続管理・ネットワーク切替・接続案内 | × | × | ○ |
| BMS保護・MOS・バランス・ファームウェア変更 | × | × | × |

第1段階の法人用と個人利用者用は同じ操作範囲です。法人用は導入先法人、個人利用者用は本人が設定・データ・利用を管理します。法人用という版名だけで複数利用者の認証、顧客データ分離、資格確認、解除コードが備わるわけではありません。これらは次段階で実装します。

フルアクセス用は開発者・確認済み資格者本人向けの提供区分です。現在の依頼者はこの版を使用します。資格者の対象は第二種電気工事士、または1級・2級・3級・特殊自動車整備士のいずれか。法人での資格確認・利用許可は法人管理者が担当します。第1段階のパッケージには資格証照合・本人認証はなく、ダウンロードした人の資格を自動判定しません。専用解除コードの設計は [解除方式案](ELEVATED_ACCESS_PROPOSAL.md) を参照してください。

## 導入方法

1. 対象の版を選び、ZIPを新しいフォルダーへ展開します。旧版のフォルダーへ重ねて展開しません。
2. Windowsに対応する公式Python 3.12以降を用意します。ARM64 / x64はOSとPythonの実際の組合せで確認します。
3. 配布物のクイックインストール入口を実行します。専用 `.venv` と依存関係を準備します。初回の依存取得にはインターネットが必要です。
4. 起動入口から `http://127.0.0.1:8765/` を開き、版名と「模擬」の表示、履歴保存を確認します。
5. 実機を使う場合は、管理する本人・法人が [実機確認手順](HARDWARE_VALIDATION.md) に従い、対象BMSとローカル設定を確認します。Bluetoothアドレス・秘密・測定履歴は配布物から引き継ぎません。

手動導入も利用できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Setup.ps1
.\scripts\Start.ps1
```

PythonがPATHにない場合は `Setup.ps1 -PythonExe 'C:\path\to\python.exe'` で明示します。クイックインストールはPython同梱EXE / MSIではありません。Pythonの自動ダウンロード、ドライバー変更、Firewall追加、ホットスポット切替は行いません。制限版は管理用PowerShellスクリプトを同梱せず、初版のスマホ接続設定はフルアクセス側の機能です。

全版で初期設定は模擬BMS・localhost限定・GPSと外部同期は無効です。準備後のBMS監視、SQLite保存、分析はインターネットなしで動きます。自動バックアップ等の保存保守は継続し、手動バックアップ操作の制限とは分けています。

## 制限の実装境界

版はパッケージ内 `gtbms/edition.json` から起動時に読みます。未知の版・欠落・破損は起動エラーになり、暗黙にフルアクセスへ移行しません。画面の無効化に加えAPIで管理操作を403にし、CLIでも対象の保守コマンドを拒否します。HTTPのパラメーターから版を変更できません。通常操作のCSRF保護は全版で維持します。

これは配布アプリの操作制限です。オープンソースを編集できるWindows利用者・管理者に対するDRMや耐改ざん保証ではありません。配布物に全利用者共通の解除鍵、開発者の遠隔ログイン、顧客端末への常設アクセスを組み込みません。開発者向けパッケージの所持は顧客端末・顧客データへの許可を意味しません。

現在稼働している旧サーバーと新しい画面の互換性を保つため、画面は版情報のない旧APIを従来のフル操作表示として扱います。新サーバーの制限はサーバー自身で判定するため、この画面互換処理では解除できません。

## ビルドと公開

`scripts/Build-Release.py` を開発環境で実行し、3種類を生成します。版に加えビルド識別子を付け、同じ出力先への上書きを拒否します。版ファイルはZIP内に生成し、作業端末のフルアクセス指定は変更しません。ソース・テスト・通知・許可された導入資料を含め、`.venv`、設定実ファイル、DB、GPS、実ログ、実機調査記録を除外します。

GitHubへ載せる前に公開用ファイルを抽出した作業場所で差分・秘密情報・ライセンス通知を確認し、採用コミット、版、各ZIPのSHA-256を記録します。既存の実測データを含む作業ディレクトリーで `git add .` を行わないでください。公開先は [hpingyan66-droid/gt-bms-monitor](https://github.com/hpingyan66-droid/gt-bms-monitor) です。公開したコミットとリリースの状態を別途確認します。初期版はソース付きZIPで、署名付きバイナリではありません。

## 更新と復旧

更新前のコード・ローカル設定・DBの整合したバックアップを端末内に残します。動作中のDB本体だけをコピーせず、アプリのバックアップ機能または停止後の適切な保存を使います。新しいフォルダーへ展開し、模擬確認後、本人・法人が必要なローカル設定とデータだけを移します。資格者用の版を一般利用者用へ変える場合も別フォルダーに導入します。旧版へ戻す場合は新プロセスを停止し、旧フォルダーと確認済みバックアップを使用します。
