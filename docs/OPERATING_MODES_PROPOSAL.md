## 1. 表示する指標

| ガソリン車での見方 | EV側の表示案 | 定義とデータ条件 |
| --- | --- | --- |
| 現在どれだけ動力を使っているか | 瞬時バッテリー電力 kW（詳細W） | 電圧×符号確認済み電流。正は放電、負は充電。モーター軸出力・車輪出力・定格馬力とは別 |
| 走行全体でどれだけ使ったか | 走行平均電力 kW（詳細W） | 有効区間の放電Wh÷有効計測時間h。停車を含む走行セッション内の平均。欠測率を併記 |
| 最大出力の目安 | 観測ピーク電力 kW（詳細W） | 有効な測定点で観測した最大放電電力。1秒等のサンプリングで見逃す短いピークがあり、真の瞬間最大・モーター定格出力を保証しない |
| 平均燃費 km/L | 平均電費 km/kWh、併記Wh/km | 今回走行の距離km÷放電kWh。km/kWhは大きいほど少ない電力で長く走る。Wh/kmは小さいほど少ない電力で走る |
| 使用した燃料量 L | 消費電力量 Wh / kWh | 有効区間の放電電力を時刻で積算。充電側は別欄、充電器と回生は判別できるまで未判別 |
| 残り何km走れるか | 残走行可能距離 km | 既存の履歴予測を使用。容量の参考値・実測値、信頼性を区別 |

Wは電力、Whは電力量。km/Lからkm/kWhへの一律の数値換算は行わず、実測した電力量と距離でEVの電費を計算する。馬力への単位換算でバッテリー電力をモーターの馬力として表示しない。

### 平均ピークの候補

日常の乗車画面は「平均電力」と「観測ピーク」を別表示する案を推奨する。「平均ピーク」も必要なら、詳細分析に **直近20件までの適格な終了走行の観測ピークの算術平均** を追加する。対象件数、取得周期、取得率を示し、期間内の最大値や走行平均電力とは混同しない。

この平均ピークは指標の候補であり、採用は未決定。窓ごとの最大を平均する案は、窓幅や未完了窓の扱いによって値が変わるため、初版の候補から分けている。異なる取得周期のピークは取得周期別に扱い、走行途中で周期が変わった場合は比較対象から除外する。

### 集計条件

- 電流方向未確認、異常フラグ、時計不整合、再接続境界、許容間隔を超える欠測は電力量の積算から除く。古い瞬時値を現在値として出さない。
- 平均電力は有効計測時間を分母とする。未計測時間を0Wとして全時間で割らない。有効時間0は未算出、有効計測で放電が0なら平均0Wを区別する。
- ピークは実際に取得した有効な測定点から算出し、補間した値から最大値を作らない。平均とピークそれぞれに計測率・対象期間を添える。
- 平均電費は距離が正、方向確認済み、計測率90%以上を主表示の候補条件とする。GPS距離は精度・取得率も必要。条件を満たさない場合は未算出理由を出し、部分Whは参考詳細へ分ける。
- GPSなしでも終了後の手入力距離から走行電費を出す。正確な現在速度・距離がない間は、走行中の瞬間電費や進行中の距離電費を作らない。
- 放電Wh=0ならkm/kWhは無限大にせず未算出とする。充電Whを差し引かない「放電基準の電費」を初版の提案とする。既存の正味Wh/kmは履歴互換のため別項目として保持する。
- 複数走行の実績電費は総距離÷総放電kWh。各走行のkm/kWhの単純平均にしない。既存の航続距離予測用の重み付きWh/kmとは別の指標名・データ項目を使う。
- 過去の走行に平均・ピークがない場合は未算出。元の有効測定が残る場合だけ、確認可能な方法で再計算する。過去値を推測で埋めない。

説明用の仮の例: 有効計測30分、放電600Wh、距離20kmなら平均電力1,200W、電費33.3km/kWh＝30Wh/km。ピークはこの3値から求まらず、別途測定点が必要。

## 2. 4モードの権限表（初版案）

表はSurfaceのアプリ操作を対象とする。許可は、対象車両・導入先について所有者から付与された権限の範囲に限る。走行開始・終了は乗車前・乗車後の停車中に本人が明示操作する。GPSによる自動停車確認を意味しない。

全モードで異常・欠測・未確認・模擬の表示を維持する。販売店画面でも警告を隠したり、航続距離を実測より良く見せたりしない。サービスマンがデータを取得できても、他の顧客の履歴やGPSへの権限は自動的に付与しない。

### モード切替と本人確認

- 所有者の管理権限と4種類の画面モードを内部で分ける。画面でサービスマンを選ぶだけでは権限は増えない。
- 提供先ごとに所有者を設定。サービスマン・販売店は既定で無効、所有者が許可範囲・期限を決め、失効できる案。
- 実効権限は「所有者が付与した権限」と「現在のモード制限」の共通部分。通常操作、GET履歴、エクスポート、WebSocketまでサーバー側で判定する。
- 失効・ログアウト・権限縮小は既存接続と別タブにも反映する。認証情報やGPSをログへ残さず、誰の権限で何を許可・拒否したかを記録する。
- 乗車モードは手動の操作制限状態。モード切替だけでBMS収集を開始・停止しない。GPS無効や速度不明を停車とみなして自動解除しない。
- 上位モードへ移る場合はSurfaceで認証する。乗車を解除しただけで診断・販売店権限は得られない。
- フルアクセスは登録済みの開発者・資格者が専用解除を行った場合だけ表示する案。対象導入先、対象者、期限を束縛し、アプリ機能の制限を解除する。BMS設定書き込み禁止は解除しない。コードの発行・権限付与は所有者の管理機能へ分離する。
- 現在はローカル操作者を信頼するCSRF保護とパッケージ単位の権限を使い、所有者ログインや利用者単位の役割権限は未実装。同じWindowsユーザーや管理者によるファイル編集を防ぐDRMとしては扱わない。

### スマホの初版範囲

今回の最小案ではスマホは引き続き閲覧専用。所有者が許可した監視／乗車表示を切り替える。Surfaceで開始した走行の平均・ピーク・電費要約だけを追加中継し、履歴全体・GPS・設定・管理トークンは公開しない。

表にある走行開始終了やネットワーク切替等の操作はSurface側。スマホにも開始・終了を追加する拡張案は、閲覧専用APIを変更し、認証と通信保護の設計・受入が増えるため別判断とする。

## 3. 既存実装からの差分と実装順

1. 指標定義承認後: `analysis.py` の有効区間計算を共用し、平均W・観測ピークW・km/kWh・計測率・根拠を追加。予測学習の既存指標を上書きしない。
2. 走行開始中も収集側で集計して提供する。閲覧者ごとや0.5秒ごとに全履歴を再集計しない。再起動・欠測・終了後距離修正・履歴保存を検証する。
3. PC/スマホへ指標表示。スマホ中継の許可リストを必要な数値と状態に限定し、現在の経路・更新周期を維持する。
4. 権限表承認後: 所有者認証、役割の付与・期限・失効、サーバー権限判定、4画面を実装。秘密を既存設定差分・配布物へ含めない。
5. 導入先別設定、独立デモ、配布環境・通知同梱・復旧の受入。現行ローカル設定の互換性を検証してから本体更新を行う。

API項目、走行JSON、PC/スマホ画面、認証・操作手順が変更対象。現状は走行JSONを保存する構造だが、権限・監査の保存方式は実装時に移行手順を含めて検証する。稼働中の監視への適用前にバックアップと模擬回帰を行う。

## 4. 代替案と承認事項

- 指標: 初版は瞬時・平均・観測ピーク・平均電費を推奨。平均ピークは定義が確定した詳細分析として追加する案。
- 権限: 画面だけの切替は見やすさ調整には使えるが、利用者ごとの操作制限を満たさない。サーバー判定を含む上記案を推奨。
- 提供範囲: 初版は1導入先・1所有者のローカル運用。複数顧客を販売店の中央サーバーで一括管理する機能は今回の案に含めない。
- スマホ操作: 初版は閲覧専用維持を推奨。開始終了までスマホへ公開する場合は別の変更範囲として判断する。

依頼者が決める事項は、指標名・平均ピーク採否、表の各許可範囲、スマホを閲覧専用とする初版範囲。認証方式の細部はオフライン要件・運用負担を確認して具体化する。現時点ではこの文書を承認済み仕様として実装しない。

## 5. 受入試験案

- 電力: 不均一な時間間隔、0跨ぎ、放電なし、充電のみ、符号未確認、異常値、切断epoch、時計飛び、欠測、走行境界、単一測定点、周期違いのピーク比較。
- 電費: GPSなし手動距離、距離0、電力量0、計測率不足、部分GPS、正味/放電の区別、距離訂正、実績平均と予測重み付き平均の区別。
- 権限: 全APIとWebSocketの許可/拒否、画面を通さない直接要求、期限切れ、失効、別タブ、再起動後、未知の役割、閲覧キーの管理権限への流用防止。
- 運用: モード切替中のBMS継続記録、乗車画面の操作制限、独立デモと実機の分離、スマホ通信断、従来の遅延測定、既存機能回帰。

電流方向が未確認の環境では追加指標を算出しない。瞬時電力・平均・ピーク・電費の実機受入前に、既存の読み取り専用手順で充放電方向を確認する。今回の設計作業では実機設定を変更しない。
