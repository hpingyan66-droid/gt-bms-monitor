# 0.2.1 走行推定と学習の仕様

すべて端末内の決定的な計算です。外部AI API・通信・クラウド学習は使用しません。距離・電力・登坂の表示はいずれも実機制御へ入力されません。

## 時刻・座標・センサー

AndroidのelapsedRealtime系時刻をGPS、センサー、BMSの鮮度判定に使用。記録日時は端末のUTC時計を別に保持します。GPSの原時刻と1秒処理の時刻を両方CSVへ出します。位置修正は1秒処理時点で最新の有効なGPSを適用するため、受信遅延分のずれは残ります。

GPSを採用する条件は、経過3秒以内、時刻の逆行なし、水平精度35m以下、緯度±85度以内、設定速度上限以下。前回測位との距離が「速度上限×測位間隔＋双方の精度の合計×3」を超える跳躍も除外します。未搭載や権限不足の場合に座標を捏造しません。

GPS速度精度1m/s以下の前後ペアでは、前後速度の台形積分を距離に使用します。0.35m/s未満は停止扱い。速度情報がない場合は位置の変位を利用し、精度以下の小変位を蓄積して閾値（4mと前後精度の和の大きい方）を超えてから反映します。後者は学習対象外です。

端末は常時車体へ固定する前提です。旧版の mounted=false は新規記録に適用しません。姿勢融合とジャイロが利用できるとき、線形加速度を優先（なければ加速度を姿勢行列で水平面に変換）します。回転ベクトルの磁北座標をGeomagneticFieldの偏角で真北へ回転。GPS進行方位へ加速度を投影し、鉛直軸ジャイロから旋回を積分します。端末の向きを車両前向きと仮定する必要はありませんが、車体に対して動かない取付けが必要です。

GPS停止が3回以上続き、加速度・角速度が小さい場合だけ、IMUの静止バイアスを少しずつ補正します。加速度が小さいことだけで走行中の車両を停止判定しません。IMU間隔0.2秒超、過大な入力、姿勢・ジャイロが古い場合は利用せず、設定上限で速度を制限します。

## GPS欠測と復旧

GPSの最終時刻から1.5秒後〜60秒の短い欠測では上記慣性推定を使用します。必要なセンサーがない・60秒超の場合は直前の推定速度と方位を保持します。停止や速度変化が分からないと距離を過大・過小評価します。位置誤差の表示は「最終測位精度＋2×設定最高速度×欠測秒」の保守的な目安であり、校正済みの確率分布・95%信頼区間ではありません。

復旧したGPS位置と推定終点の差を、前回の測位からの経過時間に比例させて各推定点へ配分します。修正後の各点間距離を再集計し、暫定距離を置換します。再加算ではないので二重計上を防げます。元の座標・高度・区間距離は別の列に残します。曲がった経路や同じ地点に戻った経路の形は推定値を基に残し、単に両端の直線距離へ潰しません。真の経路が分かったという意味ではありません。

GPSが停止を示し、欠測中の推定移動もゼロで、復旧時の変位がGPS精度内なら、その揺れを走行距離へ加えません。

最大7,200点の未確定区間をメモリーに保持。超過した点の元記録はSQLiteに残し、全区間の補正は行わず `unresolved_gap` として測位を再開します。処理時刻の3秒超の空白も速度×長い時間で埋めず、欠測として残します。前景サービスがOSに終了された場合は、DBに残った記録から中断セッションとして表示します。

## 高度・参考勾配

気圧はローパス処理後、44330 × (1 − (p/1013.25)^0.190294957) で相対高度へ変換。GPSの垂直精度が10m以下なら絶対オフセットを合わせ、通常測位中は緩やかに更新、欠測復旧では再アンカーします。気圧高度の復旧補正も元の値を残します。標準気圧を使う絶対高度だけを海抜として表示しません。

良好な連続GPS区間の30〜80m窓（気圧あり）で高度差/水平距離を参考勾配%にします。気圧なしでは垂直精度3m以下・60m以上の窓を要します。90秒超の古い窓、GPS復旧、品質不良、±40%超の勾配は表示を保留します。気圧変化・GPS誤差・移動が小さい場合の精度は保証できません。

## 電力積分と学習

JBD 0x03の仕様に従い、受信電流の正は充電、負は放電として解釈します。raw_current_a は受信値そのまま、画面の電力と raw_power_w は電圧×生電流です。内部の power() と既存CSVの power_w は従来どおり放電を正とする計算用の値です。異なる意味を同じ列へ上書きしません。

有効な実BLE・6秒以内・品質フラグなし・保護コード0・放電MOS ONの前後値から、1回2.5秒以下の区間だけ積分します。前後電力を直線補間し、符号が変わる区間はゼロ交差で分割して放電Whと流入Whを別々に積分します。正負を先に平均して回生を消す処理は行いません。これはサンプル間の近似で、未受信の短い回生まで復元しません。古いBMS値で長い空白を埋めません。

流入Whは充電・回生の合計です。走行中の流入は回生候補ですが、BMS電流だけで発生源やブレーキ動作は特定しません。BMS計測経路に含まれる12V電装負荷を、別の仮定負荷として二重加算しません。

学習に使う距離は、前後水平精度15m以下、速度精度1m/s以下、模擬測位でなく、GPS間隔3秒以内の区間に限定。速度0.7m/s超、前後の計算用電力がともに非負の区間だけを使います。推定・補正距離、回生、模擬GPS、デモ、未確認方向、別機器への切替区間は対象外。

有効な区間の距離と放電Whだけを100m以上かつ15秒以上まで積み上げ、Wh/kmを算出（1〜1000を採用）。間の欠測や停止・回生は合計に含めません。短い欠測があるたびに、それまでの有効データを捨てることもありません。開始直後と機器切替の隙間は電力積分しません。

全体と速度3帯（10km/h未満・10〜20km/h・20km/h以上）の平均・分散を更新します。初回の係数は1、以降は0.15の指数移動平均。走行300m以上・有効60秒以上・3つ以上の100m区間を得るとモデルを利用します。該当速度帯が不足なら全体モデル、全体も不足なら明示的な手入力電費、なければ「学習中」。BMS識別子・電流方向・設定容量・車両世代で別モデル。15秒ごとと終了時に保存します。未完了100m窓は終了時に破棄します。

## 航続距離・時間

現在電圧V、BMS残Ah、設定容量C、SOCから、残Ahは min(BMS残Ah, C×SOC/100) を使用します。予備SOC r までの近似エネルギーは max(0, 残Ah − C×r/100)×V Wh。航続kmはこの値/Wh毎kmです。時間はkm/現在速度（2km/h以上）。0%までの参考時間は残Ah×V/(Wh毎km×km毎時)です。

電池の電圧曲線や内部抵抗、保護遮断条件を同定した予測ではなく、長期の容量劣化や寒さによる利用可能容量変化にも限界があります。参考幅は電費の学習分散から最低±20%相当の幅を設けた感度表示。手入力では35%。統計的な保証区間ではありません。SOCが予備値以下なら予備までの距離・時間は0になります。

## 登坂の参考上限

P×効率/v = m×g×(sinθ + Crr×cosθ) + 0.5×ρ×CdA×v² をθについて解きます。Pは連続電気入力、mは車両・乗員・荷物の合計、vは定速、ρは1.225kg/m³、無風の仮定。表示は100tanθ%。入力される機械出力を電気入力と誤認しないよう案内します。最大表示60%まで。

重量・入力が不明、速度ゼロ等では数値を出しません。モータートルク、タイヤ径、ギア比、熱、グリップ、発進、制動、転倒、車両の公称限界を含まないため、登れることを保証する表示ではありません。学習するのは電費であり、危険な傾斜を試して限界を自動学習する機能はありません。

## 保存とCSV

BMS DB `gtbms-android.db` はschema 1のまま変更なし。走行は別の `gtbms-trips.db` schema 1。走行点、セッション集計、車両別モデルを保存します。復旧補正は該当点のmotion JSONだけを同一トランザクションで更新し、BMSのtelemetry JSONを維持します。毎秒の推定値は保存しますが、25Hzの全IMU原波形は保存しません。

走行CSVには、セッション・UTC時刻・原GPS時刻・情報源・元/補正座標・原GPS座標と精度・高度と気圧・元/補正区間距離・累積距離・勾配・BMS値・有効性・車両設定を出力。録画・マイク・カメラデータは扱いません。書き出し中は新しい走行の開始を待つため、補正と出力の競合を防ぎます。BMS CSVと走行CSVの末尾に raw_power_w を追加します。既存列の順番・意味とDBスキーマは維持し、過去JSONにこの項目がなければ新列は空欄です。過去の raw_current_a から別途計算可能ですが、今回過去記録は書き換えません。
